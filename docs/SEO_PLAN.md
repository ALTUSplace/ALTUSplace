# ALTUSplace SEO Plan

Technical and content SEO roadmap for the ALTUSplace Morocco marketplace
(car rental + real estate). This document is the source of truth for the
decisions made in the initial strategy session and the work shipped in
Phase 0.

## Locked decisions

| Area | Decision |
| --- | --- |
| Primary canonical domain | `https://altusplace.ma` |
| Localization | Locale subpaths (`/ar/...`, `/fr/...`, `/en/...`) with **Arabic as `x-default`** |
| Rendering | Edge prerender proxy for crawlers/social bots on top of the SPA |
| Site URL source | `VITE_SITE_URL` env var, falling back to `https://altusplace.ma` |

Until locale subpaths exist (Phase 1), every public URL is a single
language-agnostic document. Phase 0 therefore emits a **self-referential
canonical plus a single `x-default` alternate** — never `hreflang` pointing at
`/ar`, `/fr` or `/en` routes that do not exist.

## Current state (baseline)

- React 19 SPA (Vite) + Express/tRPC API, deployed on Vercel as static
  `dist/public` + one serverless function (`api/index.js` → `dist/api-handler.mjs`).
- Client-side SEO manager in `client/src/lib/seo.ts`; JSON-LD rendered per page.
- City landing pages at `/locations/:slug` (61 cities, 12 regions).
- Sitemap was a single hand-maintained XML file; `robots.txt` pointed at the
  `vercel.app` host.
- HTML head shipped `hreflang` for `/en`, `/ar`, `/fr` (404s) and canonical on
  the `vercel.app` host — both actively harmful.

## URL taxonomy

### Indexable now (Phase 0)

| Template | Example | Notes |
| --- | --- | --- |
| Home | `/` | `x-default` target |
| Search hub | `/search` | only the unfiltered, non-empty state is indexable |
| Locations hub | `/locations` | links to all city pages |
| City page | `/locations/casablanca` | noindex while it has zero active listings |
| Bespoke landing | `/locations/marrakech-car-rental` | |
| Bespoke landing | `/locations/mohammed-v-airport-car-rental` | |
| Car detail | `/car/:id` | `Product` + `Offer`, `noindex` until the listing resolves |
| Property detail | `/property/:id` | `RealEstateListing` + `Offer`, `noindex` until resolved |
| Blog index | `/blog` | |
| Static/legal | `/about`, `/privacy`, `/dispute-resolution`, `/support-tickets` | |
| Legal (public) | `/conditions-utilisation`, `/politique-confidentialite`, `/mentions-legales` | Arabic markdown pages |

### Never indexable

`/admin*`, `/super*`, `/dashboard`, `/host*`, `/partner*`, `/agency-dashboard`,
`/add-car`, `/kyc`, `/profile`, `/checkout`, `/success`, `/voucher*`,
`/messages*`, `/my-bookings`, `/notifications`, `/favorites`, `/owner-login`,
`/register`, `/terms`, `/agency/register`, `/api/*`.

### Phase 1 (locale subpaths)

`/{locale}` prefix for every indexable template, e.g. `/ar/locations/casablanca`,
`/fr/location-voiture-marrakech`. `ar` pages are the `x-default`; each locale
page cross-links the full `hreflang` set. `/help` (redirect) and other 30x
routes are excluded.

### Phase 2 (entity/intent pages)

- Car-type hubs (`/cars/suv`, `/cars/automatic`, ...) — requires a
  `vehicleType`/`brand`/`model` taxonomy in `drizzle/schema.ts`.
- Public agency profile pages (`/agencies/:slug`) — requires a public agency
  route (only the authenticated `/agency-dashboard` exists today).
- Neighborhood/district pages for Casablanca, Marrakech, Tangier, Rabat.
- Guide content cluster (existing `/blog`).

## Phase 0 — Technical SEO foundation (shipped)

1. **SEO manager hardened** (`client/src/lib/seo.ts`): self-referential
   canonical, `x-default` alternate, full Open Graph/Twitter set (`og:type`,
   `og:image`, `og:locale`, `twitter:card`/`image`), per-page `robots`,
   env-driven `VITE_SITE_URL`.
2. **Detail pages** (`CarDetails`, `PropertyDetailWithVideo`): `useSEO` with
   listing-aware title/description/OG image; `noindex` until the listing
   resolves.
3. **Thin-content controls**: `/search` is `noindex, follow` whenever filters,
   sort, map view or an empty result set are active, and always canonicalizes to
   `/search`; empty city pages are `noindex, follow`.
4. **Sitemaps**: static sitemap **index** (`/sitemap.xml`) referencing
   `/sitemap-static.xml`, `/sitemap-cities.xml` and two runtime sub-sitemaps
   (`/api/sitemap-listings.xml`, `/api/sitemap-companies.xml`) generated from
   the database so fresh inventory is picked up without a redeploy. The static
   parts are generated by `scripts/generate-sitemap.ts` (runs before
   `vite build`).
5. **`robots.txt`** rewritten for `altusplace.ma`, adding `/super*`,
   `/favorites`, `/owner-login` and the sitemap index.
6. **Domain canonicalization**: `www.altusplace.ma` → `altusplace.ma` (301) and
   `trailingSlash: false`.
7. **Edge prerender**: `server/_core/prerender.ts` builds crawler/social HTML
   (title, description, OG, canonical, JSON-LD), reused by the Node static
   server and exposed as `GET /api/prerender`; `middleware.ts` proxies bot
   user-agents to it at the edge.

## Domain migration runbook (`vercel.app` → `altusplace.ma`)

The apex domain is canonical in code, but the `vercel.app` → `altusplace.ma`
host redirect is **staged, not active**, so the current deployment is not
broken before DNS is attached. To complete the migration:

1. Add `altusplace.ma` and `www.altusplace.ma` to the Vercel project.
2. Set `VITE_SITE_URL=https://altusplace.ma` in the Vercel project env (all
   environments) and redeploy.
3. Add this redirect as the **first** entry in `vercel.json` `redirects`
   (keep it until Search Console confirms the move; 301s are cached, so all
   hosts must be verified in GSC first):

   ```json
   {
     "source": "/(.*)",
     "has": [{ "type": "host", "value": "altusplace.vercel.app" }],
     "destination": "https://altusplace.ma/$1",
     "permanent": true
   }
   ```

4. Re-submit `https://altusplace.ma/sitemap.xml` in Google Search Console and
   use the Change of Address tool.

## 90-day roadmap

| Window | Focus | Exit criteria |
| --- | --- | --- |
| Days 0-14 (Phase 0) | Technical foundation above | Green `pnpm check`/`test`/`build`; GSC shows canonical + sitemap accepted; no `hreflang` to 404s |
| Days 15-45 (Phase 1) | Locale subpaths + `hreflang` matrix; agency public profiles; car-type hubs seed | `/ar`,`/fr`,`/en` routes live with reciprocal `hreflang`; first entity pages indexed |
| Days 46-75 (Phase 2) | Content cluster expansion (guides, city+intent, districts); internal linking; CWV/INP pass | 30+ content URLs, top-20 rankings on long-tail city queries |
| Days 76-90 (Phase 3) | Authority + measurement: citations, reviews, Core Web Vitals dashboard, GSC/Bing wiring | Baseline CWV "Good"; tracked keyword + impression growth |

## Measurement

- Google Search Console (both hosts during migration) + Bing Webmaster Tools.
- Core Web Vitals via CrUX/GSC; keep the `vendor` chunk budget under review.
- Track: indexed URL count, impressions/clicks by city template, rich-result
  eligibility (Product / RealEstateListing), and crawl stats for `/api/prerender`.

## Technical guardrails

- `pnpm check` must stay at 0 TypeScript errors; `pnpm test` green; `pnpm build`
  succeeds (the sitemap generator is part of `build`).
- Never emit `hreflang` for a URL that is not reachable and canonical.
- Any new indexable template must register in `server/_core/sitemap.ts`
  (static/administered routes) and set `useSEO`.
